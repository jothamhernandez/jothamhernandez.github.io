# SEO & metadata

SEO for this site is split across a data file, the page's `useHead`, config, and
static files. Change the right layer.

## Where each piece lives

| Concern | Location |
|---|---|
| Title, description, keywords, OG/Twitter meta | `app/data/seo.json` → consumed by `useHead` in `app/pages/index.vue` |
| Canonical URL + `og:url` | `seo.canonicalUrl` in `app/data/seo.json` |
| Social share image | `seo.ogImage` (used for `og:image` + `twitter:image`) |
| Twitter handle | `seo.twitterHandle` |
| JSON-LD structured data (schema.org Person) | inline in `index.vue` `useHead().script` |
| Sitemap | `@nuxtjs/sitemap` module + `site` block in `nuxt.config.ts` (served at `/sitemap.xml`) |
| Robots directives | `public/robots.txt` |
| Google Analytics (GA4 `gtag`) | `app/app.vue` `useHead().script` (measurement ID `G-LMPTJSNQ9T`) |

## Editing standard meta

Edit `app/data/seo.json` — `index.vue` maps it to title, description, keywords,
Open Graph, Twitter card, canonical link, and Person JSON-LD. `keywords` is an
array joined with commas at render time. Keep `title` ≲ 60 chars and
`description` ≲ 155 chars for clean SERP display.

## Domain consistency (aligned on `www` — keep it that way)

Search engines treat `www` and apex as different origins, so the canonical host
must be declared identically everywhere. The site is standardized on
**`https://www.jothamhernandez.com`** across all three of these — if you change
one, change all three, and make sure DNS 301-redirects the apex to `www`:

- `app/data/seo.json` → `canonicalUrl` and `ogImage`.
- `nuxt.config.ts` → `site.url` (feeds the sitemap module).
- `public/robots.txt` → the `Sitemap:` line.

## Social share image

`seo.ogImage` points at the absolute URL `https://www.jothamhernandez.com/og-image.png`,
and a real 1200×630 branded card lives at `public/og-image.png`. Crawlers require
an **absolute** URL and a raster format (PNG/JPG — not SVG). If you restyle the
card, regenerate it at 1200×630; it was produced with ImageMagick (`magick`) from
brand tokens (zinc text, `#854d0e` accent, Georgia serif). After deploy, verify
previews with the LinkedIn Post Inspector / X Card Validator.

## JSON-LD structured data

The `schema.org/Person` block is built inline in `index.vue` from `profile`
fields (`name`, `currentRole`, `linkedin`, `orcid`, `googleScholar`) and
`seo.canonicalUrl`. Update those data files and the JSON-LD updates with them.
To add fields (e.g. `alumniOf`, `knowsAbout`, `email`), extend the object in the
`useHead().script[type=application/ld+json]` entry. Validate with Google's Rich
Results Test.

## Sitemap & robots

The sitemap is auto-generated by `@nuxtjs/sitemap` from routes, using
`nuxt.config.ts` `site.url` as the base. After adding a new page (a real route
under `app/pages/`, not an in-page `#anchor`), it appears automatically —
in-page anchors are not separate URLs and won't be listed. `public/robots.txt`
currently allows all crawlers; keep the `Sitemap:` URL host in sync with the
chosen canonical host (see above).

## Analytics

GA4 is loaded globally in `app/app.vue`. To change the property, replace the
measurement ID `G-LMPTJSNQ9T` in both the script `src` and the `gtag('config', …)`
call. To add event tracking, call `gtag('event', …)` from the relevant component.
